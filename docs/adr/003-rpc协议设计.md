# ADR-003 · RPC：持久 socket + 二进制分帧 + 批量/设备端条件，附 u2 兼容层

> 状态：已接受 · 日期：2026-11-19
> 规格：docs/02-protocol.md

## 背景

u2 体系（Python/Rust 同理）的性能天花板是**每条指令一次 HTTP/JSON-RPC 往返**（文献：click ~263ms、exists ~26ms）。本机实测注入底噪仅 ~3ms——往返协议是唯一的大头。

## 候选

| 方案 | 往返 | 体积 | 复杂度 |
|---|---|---|---|
| A. 沿用 HTTP/JSON-RPC（u2 wire） | 每调用 1 次 | 大 | 低，但天花板照旧 |
| B. 持久 TCP + 二进制分帧 + 批量/条件 opcode | 单连接复用；批量 N→1 | 小 | 中 |
| C. B + u2 JSON-RPC 兼容层并存 | 同 B | 同 B | B + 一个编解码翻译层 |

## 决定

**选 C。** ~~控制通道（BATCH/INJECT/QUERY/…）与媒体通道（FRAME）在同一 socket 上分 channel 复用~~（ADR-004 修正：media 帧流未来走第二条独立 socket，禁止跨通道交错；ch 字段保留）；`wait_until` 作为 opcode 在设备端执行，消除"条件等待"的跨端往返。

兼容层：agent 另开 u2 wire 端口，实现方法子集做编解码翻译（语义不变），用途限定为**对拍与降级**——可接 python uiautomator2 客户端做 A/B，M1 前也可直接 forward 到 u2.jar。

## 关键设计取舍

- **msgpack 先行**：Rust `rmp-serde` + Java `msgpack-core` 零原生依赖；FlatBuffers 列 v0.2 评估项，不阻塞。
- **批量非原子**：UI 自动化无回滚，fail_policy 仅决定失败点后行为。
- **媒体通道可丢帧**：背压时丢 FRAME 保控制通道。
- **不做独立规则 DSL/Lua**：条件-动作下沉 = 参数化 wait_until + 简单组合，够用即停，需求实证后重评（atx-agent 前车之鉴：设备端功能膨胀是维护成本之源）。

## 后果

- 正面：核心性能命题成立——单连接 + 批量把"每指令 1 往返"改写为"每序列 1 往返"；设备内 3ms 注入可真正兑现到 e2e。
- 正面：兼容层给出可证伪的对照实验，防止自研协议在盲区退化。
- 负面：两套 wire 需短期并存（翻译层只编解码不养语义，控制维护面）；协议演化需 HELLO 版本协商纪律。
- 验收挂钩：M2 验收线"10 步序列往返=1、摊销注入 ≤5ms"即本 ADR 的可证伪承诺。
